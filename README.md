# Distillation Job Scheduler

A classroom tool for running MLX distillation/fine-tuning jobs on a shared
Mac Studio. Student teams submit jobs through a web UI; jobs execute one at
a time (strict FIFO) via [Dagu](https://github.com/dagu-org/dagu).

```
Browser ──▶ SvelteKit app (port 3000) ──▶ Dagu REST API (port 8081) ──▶ mlx-lm
                                                       │
                                              ~/.distill/{jobs,results}
```

## Quick start (on the Mac Studio)

```bash
git clone https://github.com/Valley-Christian-Startup-Incubator/moonshine.git
cd moonshine
./setup.sh
```

`setup.sh` installs Dagu, creates a Python venv with `mlx-lm`, builds the
SvelteKit app, lays out `~/.distill/`, and registers two launchd services
(`com.distill.dagu`, `com.distill.web`) that start on boot. It prints the
web UI URL, admin password, and Dagu credentials at the end — **save that
output**, it's the only place the generated passwords are shown in full
(they're also written to `~/.distill/env`, `chmod 600`).

Re-run `./setup.sh` any time to update the stack in place; every step is
idempotent.

## Using it

- **Students**: open `http://<mac-studio-ip>:3000`, pick a team and job
  type, drop an input file, submit. Track progress on `/jobs`.
- **Admins**: `http://<mac-studio-ip>:3000/admin` — cancel jobs, check
  Dagu health and disk usage. Password is generated by `setup.sh` (or set
  `ADMIN_PASSWORD` before running it).
- **Operators**: the raw Dagu UI at `http://<mac-studio-ip>:8081` shows
  every DAG run, retry, and log — useful when debugging a stuck job.

## Manual service control

```bash
~/.distill/start.sh   # start Dagu + web app without touching launchd
~/.distill/stop.sh    # stop both
launchctl list | grep com.distill   # check launchd-managed services
launchctl unload ~/Library/LaunchAgents/com.distill.{dagu,web}.plist  # disable boot-start
```

## Job types

| Type          | Runs                              | Default timeout |
|---------------|------------------------------------|------------------|
| `prompt-gen`  | `scripts/prompt_gen.py` (skeleton — customize for your project) | 30 min |
| `teacher-gen` | `scripts/batch_generate.py` → `mlx_lm.generate` | 4 hr |
| `finetune`    | `mlx_lm.lora --train`             | 12 hr |
| `quantize`    | `mlx_lm.convert -q`               | 4 hr |

Workflow definitions live in `dagu/dags/*.yaml`. Each writes
`~/.distill/results/<job-id>/{log.txt,status.json,output...}`; the web app
reads those files directly (no database).

## Known version-drift risks

Two things in this repo pin to a specific external API surface and may need
adjustment if you're on a different release:

- `web/src/lib/server/dagu.ts` — targets Dagu's `v1` REST API. If job
  submission/cancellation fails after `setup.sh` installs a newer Dagu,
  check that release's REST API docs and adjust the paths in that one file.
- `scripts/batch_generate.py` — targets `mlx_lm.generate()`'s current
  Python API. If `mlx-lm` changes its `temp`/sampler argument shape, this
  is the only file that needs updating.

`DAGU_VERSION` in `setup.sh` is pinned explicitly — bump it deliberately
rather than tracking `latest`.

## What's intentionally not here

No auth beyond the admin password, no email notifications, no CLI client,
no automatic data retention/cleanup, no logit-based distillation (the
workflow is response-based: generate teacher completions, then SFT the
student on them). See the project brief for the full list.
